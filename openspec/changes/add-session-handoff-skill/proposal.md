## Why

跨项目或跨 agent 接续工作时，目标、证据、未提交改动和授权边界容易丢失。需要将可见上下文整理为独立可读、包含可解析元信息的交接文档，让接收方知道从哪里继续并如何验收。

## What Changes

- 在本仓库建立 `skills/session-handoff`，包含生成流程、元信息契约和可裁剪模板。
- 支持完整目标或指定子任务交接、既有文档更新、上下文缺失及失败状态披露。
- 增加仅用于开发的元信息校验工具、合成验收案例和回归测试。
- 提供使用、手动安装、能力限制和维护说明；按用户选择提供 MIT 许可证。
- 保留本地原交接材料，但排除出 Git；不创建远端、不推送、不安装全局副本。

## Capabilities

### New Capabilities

- `session-handoff`: 从可见会话生成准确、可携带且保留授权边界的交接材料。
- `handoff-metadata`: 规定并验证交接文档的 YAML 元信息与更新行为。

### Modified Capabilities

无。初始化检查确认没有已有规范。

## Impact

唯一编辑源为当前仓库，这是用户指定目录的独立项目，不在个人能力集合中重复维护。skill 使用时只需能读写 Markdown 的 agent；Node.js 和 YAML 解析包仅用于仓库开发校验。没有服务器、API、数据库、网络调用或自动安装行为。
