## Context

见 proposal.md 的动机。起点只有本地交接文档，无代码、无历史规范。原材料含个人路径，不能直接成为开源示例。用户明确选择 MIT；源位置明确指定为本仓库。

## Goals / Non-Goals

**Goals:** 提供不依赖某一 agent 私有会话存储的 Markdown skill；元信息可机器解析；用合成输入和可观察的输出检验边界。

**Non-Goals:** 不实现聊天历史导入、会话迁移、网站、监控、自动发布或全局安装。

## Decisions

1. **轻量指令与渐进披露。** 核心流程放在 SKILL.md，字段契约放在 references/metadata.md，输出骨架放在 assets/。不加入运行时脚本或特定厂商工具依赖；替代方案是构建会话导出器，但会引入权限和格式耦合。
2. **以 YAML 1.2 作为元信息语法。** 采用交接材料建议的 11 个字段；版本和日期必须是带引号字符串，未知来源和工作空间为 null。状态保留非空字符串以适配不同工作流，不锁定枚举。
3. **开发工具只读校验。** 使用 Node.js 内置测试和 YAML 解析包，校验字段类型、真实日期、重复键、日期顺序、正文存在和修订时 created 不变。CLI 不回显输入内容，避免错误信息泄露秘密。语义准确性依靠合成案例审阅；不声称格式校验能验证事实、脱敏或授权。
4. **可携带与最小采集。** 默认生成当前项目 handoffs/ 下的文档，用户指定路径优先；原始会话不入库，公共示例仅使用虚构信息。读不到的附件和未复验结论显式说明。
5. **本地 Git 基线。** 先提交忽略规则和 OpenSpec 设计基线，再提交实现与验证记录。只暂存审查后的明确路径，保留活动 change，不自动归档。

## Risks / Trade-offs

- [模型可能把建议写成事实] → 指令要求证据标签；提供失败、子任务和缺失上下文案例，逐项核查输出。
- [结构校验无法证明语义正确] → 验证报告分别记录自动检查和人工语义审阅，不将参考输出冒充跨模型实测。
- [文档携带路径、身份或秘密] → 仅保留必要路径并标明源环境；示例使用虚构值，本地原材料忽略，不回显校验输入。
- [复制安装后与源码脱节] → 安装说明要求只编辑仓库，复制前保留目标旧版并比较差异；本次不执行全局安装。

## Migration Plan

这是全新 skill，没有数据迁移。交付仓库中的 skill 目录，可由用户在目标 agent 的技能目录安装。更新时保留既有交接文档 created，并只改变真实发生变化的信息。回退可恢复先前 Git 版本的 skill；运行校验不会写回文档。
