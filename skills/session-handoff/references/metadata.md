# 交接元信息契约 v1.0

文档使用 UTF-8，第一行为独立的 `---`，以另一个独立的 `---` 结束 YAML 1.2 mapping，随后是非空 Markdown 正文。不要把整份文档包在代码围栏里。键不得重复。

| 字段 | 必需类型与含义 |
| --- | --- |
| `title` | 非空字符串，交接主题 |
| `type` | 字符串，固定为 `session-handoff` |
| `schema_version` | 带单引号或双引号的字符串，当前为 `'1.0'` |
| `created` | 带引号的真实 `YYYY-MM-DD` 日期字符串，首次生成日期 |
| `updated` | 带引号的真实 `YYYY-MM-DD` 日期字符串，实际修订日期，不早于 created |
| `status` | 非空字符串，描述被交接工作的状态，例如 planning、in-progress、blocked、completed；不是执行授权 |
| `tags` | 至少一个非空字符串的 YAML 列表 |
| `language` | 非空语言标识字符串，例如 zh-CN、en |
| `source_agent` | 非空字符串或 YAML `null`；来源 agent 未知时为 null |
| `source_workspace` | 非空字符串或 null；来源环境未知时为 null |
| `target_workspace` | 非空字符串或 null；目标未指定时为 null |

以上字段均必须出现；“未知”不等于空字符串，不要把 `null` 写成带引号的 `'null'`。默认使用字面量和列表，避免自定义 YAML 标签、锚点与别名，便于其他工具读取。可增加确实有用的分支、提交等字段，不携带秘密；未定义扩展字段不验证业务含义。

新生成和规范导入的文档还必须包含四个路由字段；旧 v1.0 文档缺少整组时仍可校验，出现任一个字段则须整组有效：

| 字段 | 类型与含义 |
| --- | --- |
| `handoff_id` | 小写 UUID v4 字符串，完整稳定身份，随机生成 |
| `created_at` | UTC 毫秒 ISO 字符串，例如 '2026-10-21T02:03:04.005Z'，身份创建时刻 |
| `source_project` | 来源项目简称，规范化后最多 32 个 Unicode 字符 |
| `topic` | 主题简称，规范化后最多 48 个 Unicode 字符 |

路由字段及文件名规则见 [收发与命名规范](routing.md)。created_at 负责命名身份，created/updated 负责内容日期：导入旧文档时前者为导入时刻，后两者保留原值。UTC 命名时间与本地内容日期可跨日，不应强行要求日期相等。

标题、状态、标签、语言和路径应引用为字符串。Windows 路径优先用单引号，如 `'D:\work\demo'`；单引号值中出现 `'` 时写成 `''`。不要对包含秘密的输入仅加引号后原样输出；应先省略秘密值。不能机械替换未转义的标题进 YAML 模板。

日期按用户当地日期填写；未知时先取得日期，不从模板、旧文档或示例复制一个当前日期。更新时读取原版保留 created，更新 updated、status 和正文中的变化；若原 created 无效或未知，说明问题并取得依据，不静默重置。

元信息和正文必须一致：completed 不能掩盖未完成验收；target_workspace 不能把建议目录当成已确定目标。来源路径仅说明源环境位置，不证明接收方能访问它。生成时目标未知为 null，投递可只在 incoming 副本补全实际目标，不改变 outgoing 原件或工作状态；正文若说目标未定，应明确是生成时状态。

校验器覆盖语法、字段类型、引号、日历日期、日期顺序、正文存在、路由字段完整性，以及提供原版时 created 与已有路由身份不变、updated 不回退；send 另检查实际文件名、源位置和目标匹配。不会证明语言、状态、工作空间、事实、授权或脱敏正确，也不会证明 updated 就是实际修订日期。
